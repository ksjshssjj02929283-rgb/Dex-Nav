# 角加速度约束与 TOPP-RA 可行性分析

> 状态：**分析结论，未实施**。
> 结论摘要：现状速度剖面在贝塞尔圆角的进出口处角加速度**超限 5.8 倍**；
> 完整 TOPP-RA 既满足约束又**比现状快 0.74 s**，不存在"安全换速度"的取舍。
> 但它有一个硬前置条件（路径必须解析可微），建议先改几何。
>
> 记录日期：2026-08-29

---

## 0. 提法修正：ω 不是自由度

差速底盘沿**固定路径**行驶时，角速度不是独立自由度：

```
ω = κ(s) · v
```

所以不存在"线速度和角速度两个量要同步规划"这回事 —— 只有一个标量时间参数化
`s(t)` 需要确定，ω 是它的因变量。真正的问题是：**角加速度约束该怎么进这个单变量问题。**

---

## 1. 数学形式：它天然就是 TOPP-RA 的标准型

令 `x = ṡ² = v²`（与 `applyAccelerationEnvelope` 里的 U 同一个量）、`u = s̈ = a`：

```
α = ω̇ = d(κ·ṡ)/dt = κ'(s)·x + κ(s)·u

约束：|κ·u + κ'·x| ≤ α_max
```

这正是 TOPP-RA 的标准型 `a(s)·u + b(s)·x + c(s) ≤ 0`。

而**现有的线加速度双扫描是同一形式的常系数特例**：`a = ±1, b = 0, c = −a_max`。

| 约束 | a(s) | b(s) | c(s) |
|---|---|---|---|
| 线加速度 `\|u\| ≤ a_max` | ±1 | 0 | −a_max |
| **角加速度 `\|κu + κ'x\| ≤ α_max`** | **±κ** | **±κ'** | **−α_max** |
| 角速度 `\|ω\| ≤ ω_max` | 0 | κ² | −ω_max² |
| 线速度 `v ≤ v_max` | 0 | 1 | −v_max² |
| 侧向加速度 `κv² ≤ a_lat` | 0 | κ | −a_lat |

**结论：上 TOPP-RA 不是引入外来算法，而是把已有双扫描的系数从常数放开。**

---

## 2. 现状测量：问题比预想严重

在 `spacing = 0.2` 的直角圆角路径上（全长 3.785 m，ds = 0.005 m），
按 `config/path_follower.yaml` 实际参数复刻完整管线
（`dec_ratio` 上限 → `applyAccelerationEnvelope` 双扫描），再回算 α：

| 贝塞尔内位置 (m) | κ (1/m) | dκ/ds (1/m²) | 现状 v (m/s) | α 需求 (rad/s²) | 完整 MVC 允许 (m/s) |
|---|---|---|---|---|---|
| **入口 0.000** | **0.000** | **12.00** | 0.383 | **1.76（5.0×）** | **0.171** |
| 0.050 | 0.542 | 9.75 | 0.327 | — | 0.241 |
| 0.100 | 0.981 | 7.88 | 0.259 | — | 0.307 |
| 0.200 | 1.618 | 4.99 | 0.140 | — | 0.447 |
| 弯心 0.490 | 2.244 | ~0 | 0.140 | — | 0.446 |
| **出口 0.986** | **0.000** | **−12.00** | 0.419 | **2.04（5.8×）** | 0.700 |

`α_max = max_angular_acceleration = 0.35 rad/s²`

### 2.1 根因：`dec_ratio` 只看 κ，而入口的问题在 κ'

入口处 `κ = 0` → `dec_ratio = max(0.2, 0.3/(0+0.3)) = 1.0` → **一点都不减速**。

而恰恰在这一点 `κ' = 12` 达到全程最大，角加速度需求也最大。
**曲率限速在这里是结构性失明的**：它的输入量 κ 在这里恰好为零。

### 2.2 形状完全反了

- **进出口过渡段（前后各约 8 cm）：快了 2.2 倍**，α 超限最高 5.8×；
- **弯心：慢了 3.2 倍**（0.140 vs 允许的 0.446）——
  这是 `dec_ratio` 隐含 ω 软钳 `√gain/2 = 0.274 rad/s` 只用到 `max_angular_velocity` 27% 的老问题。

### 2.3 几何观察：G2 不够，角加速度吃的是 κ'

五次贝塞尔给的是 **G2（κ 连续），不是 G3 —— κ' 在入口是跳变的**
（直线段 κ' = 0 → 贝塞尔入口 κ' = 12）。而角加速度约束吃的恰恰是 κ'。

**所以"用 G2 平滑倒角"并没有换来角加速度可行性。**

## 3. 三方案对比（决定性）

| 方案 | \|α\|max (rad/s²) | 超限区间 | 总用时 |
|---|---|---|---|
| 现状（`dec_ratio` + 线加速度双扫描） | 2.036（**5.8×**） | 0.170 m | 11.73 s |
| 折中（+ κ' 逐点上限，约 5 行） | 0.469（1.3×） | 0.240 m | **12.81 s** |
| **完整 TOPP-RA（线 + 角）** | **0.350（恰好贴限，0 超限）** | **0** | **10.99 s** |

TOPP-RA 解的可行性校验：

```
|u|   ∈ [−0.399, +0.500]   限 [−0.4, +0.5]   ✓
|ω|max = 0.718             限 1.0            ✓
入口 v = 0.171   弯心 v = 0.314   贝塞尔内最小 v = 0.167
```

### 关键结论

> **TOPP-RA 同时更对且更快 —— 比现状快 0.74 s（−6.3%），而现状那 11.73 s 是超限 5.8 倍换来的。
> 这里不存在"安全换速度"的取舍。**

反倒是那个便宜的折中方案两头不讨好：把 5.8× 压到 1.3×（主要矛盾确实解决了），
但因为 `u = 0` 的假设在过渡段过保守、弯心又仍被 `dec_ratio` 卡在 0.14，**反而慢了 1.08 s**。

## 4. 副产品：一条圆角设计公式

入口曲率变化率有精确的标度律（在 spacing = 0.1 / 0.2 / 0.3 / 0.5 / 0.8 上验证，五位数字全等）：

```
κ'_entry · spacing² = 0.48

=>  v_entry ≤ spacing · √(α_max / 0.48) = 0.854 · spacing     (α_max = 0.35)
```

spacing = 0.2 → 0.171 m/s，与数值解完全吻合。

**要 0.7 m/s 入弯，需要 spacing ≥ 0.82 m**，即圆角偏移 `d = 3 × spacing = 2.46 m`
—— 比 2 m 的直边还长。**这个几何根本不可能高速通过，与用什么速度规划器无关。**

对比之前那条 `κ_max · d = 1.3464` 给出的 spacing ≥ 0.44 ——
**κ' 才是真正的瓶颈，比 κ 严一倍。**

## 5. 实现代价：比"TOPP-RA"这名字轻得多

通用 TOPP-RA 每步要解 LP，但在这个问题里 **u 是标量、约束只有 3~5 条**，
可行 u 区间就是几个区间求交，闭式，约 20 flops/点。**不需要引入 solver。**
结构与现有 `applyAccelerationEnvelope` 同构（同样的 x = v² 空间、同样的前后向两遍）。

### 顺手可以升级的：轮级约束

差速底盘真实的物理限制是**轮级加速度**，而不是人造的 `(a_max, α_max)` 方框：

```
v_{L,R} = ṡ (1 ∓ κb/2)
v̇_{L,R} = u (1 ∓ κb/2) ∓ (b/2) κ' x
```

同样是 TOPP-RA 标准型。方框约束在弯中过保守、在入口又不够，
换成轮级约束既更准也更快。

## 6. 三个真问题

### 6.1 一遍扫描的正确性证明失效

现状"先反后正一遍即最终解"，靠的是 u 的界是**常数**。
加角约束后 u 的界依赖 x（`u ≤ (α_max − κ'x)/κ`），反向传播不再单调，
必须换成 TOPP-RA 正规的**可控集 / 可达集**递推。

这是整个改动里唯一有智力含量、**必须照论文写而不能凭直觉改**的部分。

### 6.2 κ' 是路径的二阶导 —— 这是硬前置条件

现有 κ 已经是三点圆法算出来的，再差分一次得 κ'，在真机来的 nav2 折线路径上会炸：
**κ' 直接乘 x 进硬约束，一个噪声尖峰就能把 MVC 压到 0。**

之前讨论线加速度包络时说的"不考虑曲率噪声"在那里成立
（κ 只进 `dec_ratio`，噪声只让车偶尔慢一下）；**但 κ' 让噪声变成一等公民，这次挥不掉。**

> **TOPP-RA 的前提是路径解析可微。**
> 自己生成的贝塞尔圆角有闭式 κ'（本文数值即由闭式算得，与有限差分吻合到 1e-9），完全没问题；
> 外部规划器丢过来的折线，必须先做曲线拟合，否则免谈。

### 6.3 没有 jerk 限制

TOPP-RA 是时间最优的 bang-bang 解，加速度在切换点不连续。
现状走 Ruckig（`max_linear_jerk: 0.2`）——
不过 `applyAccelerationEnvelope` 现在本来也是 bang-bang，
jerk 限制只在包络不起作用的地方还活着，所以这条损失没有听起来那么大。

## 7. 结论与建议

**技术上合适，而且是这个问题的正解 —— 但不建议现在就上。**

不是因为算法不对（数据摆在那儿：更对且更快），而是因为在
"κ 来自三点圆法、κ' 有跳变、路径来源不保证可微"的现状下，
上了它算出来的东西不会比现在更可信。先把地基铺好：

1. **先确认路径来源。**
   如果 `path_follower` 只吃自己生成的贝塞尔 / 样条路径，κ' 有闭式，可以直接上 TOPP-RA；
   如果要吃 nav2 的折线，先解决曲线拟合 —— 这是硬前置。

2. **几何这一层可能比算法更值钱。**
   瓶颈是 κ' 在入口的跳变，那么 ——
   **clothoid（回旋线）的定义就是 κ' = const**，
   它恰好是"匀速下角加速度恒定"的曲线，公路 / 铁路缓和曲线用它正是这个理由。
   用 clothoid 接直线，κ' 从 0 连续过渡，0.171 m/s 那道硬墙直接拆掉。
   或者升到**七次贝塞尔**（每边 3 个共线控制点）拿 G3。

   > **在错误的几何上跑最优算法，收益远不如把几何改对。**

3. **那 5 行的折中（κ' 逐点上限）只当临时止血用。**
   它把 5.8× 压到 1.3×，但慢 1.08 s。
   短期内要跑产线又不想被 5.8 倍超限咬到，可以先垫上，但别当终点。

### 建议的下一步（低成本、高信息量）

**把 κ' 也算出来并打进日志 / 话题**，在真机的实际路径上看一眼它的噪声水平。

这个数据决定了 TOPP-RA 到底是"值得做"还是"做不了"，代价只有几十行。
